# 技能演进插件 · 用户使用验收

适用插件 `dsh-openviking-skill-evolution`。从一条普通对话开始，依次确认插件能发现值得保留的做法，让用户看懂变更，按设置处理提案，并在需要时恢复原版本。下列是验收计划，需由执行会话填写实测结果。

## 1. 环境与夹具

- **固定被测包。** 首轮选取包含当日修复的 `0.2.5` 候选包。仓库现有同名 `.tgz` 实测 SHA-256 为 `742272b5afcc87f150268030fbdd2eb9c6a3de976fd78e708f597634c225459f`，对应公开 Release。项目记录中的修复候选 SHA-256 为 `ed6d26efd997e822396543b6d928efbd31639b15f9b8627c39f7bd734b99d8de`，以实际取得的文件核对为准。若候选不可得，从固定源码快照打包并记录 commit、工作树差异、包哈希和已加载文件校验。用公开包做对照时单独出结果。宿主参考 macOS、DSH `0.2.2-rc.5`、OpenViking `0.5.5`，报告填实际版本。
- **每组拥有自己的环境。** 启动前配置独立 DSH profile、Documents、会话和随机端口，启动后核对实际路径。用独占浏览器标签或可隔离浏览器实例。写入组用单写者 OpenViking 测试实例或专用测试账号。共享技能场景也用隔离实例。当前桌面、个人技能库、历史会话和凭据保留给正常使用。必须共用的浏览器或资源按组串行操作。
- **区分证据来源。** 用户操作走插件面板、普通会话或斜杠命令。确定性模型与服务夹具可以生成指定输出或故障。运行记录、事件与回读作为辅助证据。真实模型、真实 OpenViking、真实宿主配夹具、源码/单测四种来源按用例记录。真实用户流程至少尝试一次隔离环境中的实模型自然对话，有前置缺失时登记阻塞。
- **准备数据。** 每组用独立 `[RUN_ID]` 和技能名。建立普通会话 A，再建立 B。建一份私有 `uat-[RUN_ID]-release-check/SKILL.md`，带合法 YAML 元数据，正文中有唯一一行 `运行发布检查。`，再放一份既有 UTF-8 附件 `references/baseline.md`。正文、附件列表与各自 SHA-256 留作初始快照。按各用例从快照重新播种，或为每一用例使用独立技能副本。

日常对话样例。把预检限定为夹具中的纯文本检查，例如核对约定标记和退出状态。

1. 「先完整读取这份发布检查技能 `[PRIVATE_SKILL_URI]`，按它检查这次模拟发布，告诉我结果。」确认工具成功返回完整正文。
2. 「刚才结论漏了退出状态。下次请先核对退出状态，再报告结论。请按这个顺序重新检查一次。」
3. 前台学习用例接着说「把刚才验证通过的步骤保存到这份技能，顺便加一份简短的核对清单。」后台专测用例在第 2 步要求 Agent 只完成检查，把经验交给会话复盘。要稳定触发自动复盘，可在反馈里加入当前设置中的关键词「技能纠正」，仍用自然语言叙述。先等当前轮结束，再观察运行历史。加测阈值时，可在隔离环境中调低「高级设置」的轮数门槛，用无触发词的普通对话对比达到门槛前后的表现。

需要稳定的正文提案时，另起普通会话并完整读技能，提交以下四行，替换为测试技能的完整 URI。手动复盘用例可把「高级设置」的纠正短语改为一个专用标记并保持未达其他阈值，避免后台抢先消费证据。

```text
技能纠正 [PRIVATE_SKILL_URI]
原文：运行发布检查。
改为：运行发布检查并核对退出状态。
原因：实际检查确认，漏读退出状态会让结论缺少依据。
```

## 2. 按场景执行

`P0` 为主流程与数据完整性门槛。每例按「操作 → 可观察结果」执行，组内按编号推进。复盘体验以页面和会话表现为准，写入结果须另外核对 OpenViking 原始内容。

| ID | 优先级 | 用户操作 | 通过条件 |
|---|---|---|---|
| A01 | P0 | 在新 profile 配好测试 OpenViking 记忆连接，从「插件 → 添加插件」安装固定包，按宿主提示启用或重载，进入「设置 → 技能演进」。 | 页面出现设置、概览、提案、运行历史、技能治理、用量与记忆。新装默认自动更新，能看到连接说明，高级设置默认收起。初始空状态可辨识。 |
| A02 | P0 | 先在普通会话完整读取夹具，再断开插件写入连接或用只读测试夹具。保留自动更新，用四行纠正和手动复盘生成提案。随后切到关闭，在另一会话提交带触发词的反馈并尝试手动复盘。 | 无连接时显示实际行为为只保存草稿，能预览且远端无写入。关闭后面板有相应提示，手动入口不可运行，对应轮不产生自动复盘或学习提案。 |
| A03 | P1 | 保存明确的只保存草稿及一项高级设置，刷新并重启隔离宿主。有旧版包时再从旧版升级到候选。 | 所选模式和设置在刷新、重启或升级后保持。间隔按分钟显示。提供商与模型留空后，用一次实际模型复盘核对沿用来源会话路由。 |
| B01 | P0 | 在 A 中积累待复盘证据，后来新建 B。打开较旧的 A，进入面板留空点「运行复盘」。再显式填入有独立证据的 B 的 ID 重跑。可加测热装前已存在的 A。 | 第一次只处理 A，第二次处理 B。以运行记录中的会话 ID 和各自独有标记确认。已有普通会话可选用。 |
| B02 | P1 | 无当前会话且不填 ID，再分别输入未知 ID、打开空白会话、对无新增活动的已复盘会话重复运行。 | 分别显示选择提示、会话不可用、无活动、已复盘等对应反馈。提案数与远端技能快照保持原值。 |
| B03 | P0 | 在未自动消费证据的会话输入四行纠正，执行 `/skill-review`。另用独立快照执行 `/skill-refine` 查看候选，再执行 `/skill-refine [PRIVATE_SKILL_URI]` 查看精确 diff。 | 即时复盘能在对应会话产生预期提案。精确修订命中指定 URI 与唯一原文，预览只包含预期正文改动，能追溯到原读取与纠正。 |
| B04 | P0 | 选择只保存草稿，按自然对话样例操作，达到自动触发条件后从历史查看结果。立即刷新，观察同批证据，再在冷却期内补充一条触发反馈。 | 可从历史关联到自动复盘来源、会话和结果。模型可以给出有依据的提案或 `no_change`。同批证据无重复提案，冷却期内无第二次自动模型请求。真实模型给出无变更时，另用确定性夹具完成「可复用反馈 → 提案」的通过判据。 |
| B05 | P0 | 用合成模型响应让一轮手动复盘在 `stream` 或 `validate` 失败，恢复正常响应后，对同一会话和同批证据再点运行。 | 首次历史显示失败、阶段与可解释错误码且无写入。恢复后复盘可继续执行，无需追加无关消息。没有可控响应时记录阻塞。 |
| C01 | P0 | 在确认后更新模式，让 Agent 从普通对话用 `skill_manage` 检查基准，提交正文和 `references/checklist.md` 的变更。展开提案预览，点击批准后先取消。 | 提案待处理，正文差异和附件路径与内容均可预览。取消后仍待处理。远端正文、既有附件与目录快照维持原值。 |
| C02 | P0 | 批准 C01，重新读取技能，再点回滚并确认。 | 应用后正文和新增附件准确回读，YAML 及既有附件保留。回滚后正文与既有附件哈希恢复，新增附件移除，提案状态对应恢复结果。 |
| C03 | P0 | 在独立夹具里分别驳回待处理提案、提交后先从测试端更新基准再尝试批准。批准后又有外部修改的情形可另测回滚。 | 驳回可从面板确认，远端无写入。基准过期显示冲突或相应结果，外部版本具备独立回读证据。回滚冲突保留当前远端版本。 |
| C04 | P0 | 在有连接的自动更新模式下，用同类前台任务提交一份新的私有技能或对私有技能作小改进。 | 合格提案无需批准即应用。新对话从 OpenViking 读取到预期内容，面板有应用记录和相应回滚入口。若走新建，核对技能名和描述。 |
| C05 | P0 | 使用隔离的共享技能读成功后提出复盘改进，再用写入轨迹与共享技能快照验证。 | 支持的改进仅以本地提案出现，远端共享内容维持原值。以确有候选提案为前置，只有模型选择无变更时记为未覆盖。 |
| D01 | P0 | 在普通会话完整读取已存在的私有测试技能。到「技能治理」查看或用完整 URI 手动纳管，再归档。在同一 profile 的新会话用 OpenViking 读取工具访问同一 URI，随后在面板恢复并重读。 | 完整读取出现在治理或读取审计中。归档后插件拦截该读取，从隔离 OpenViking 服务独立回读验证原始包仍在。恢复后同一读取入口重新成功。 |
| D02 | P1 | 在测试工作区完成普通 OpenViking 记忆使用，再查看「记忆」和「用量」。准备两个不同 peer 的普通会话作对照，按面板当前观察对象核对。 | 面板显示可观察的会话、peer、读用量或相应空状态。记忆联动只按实际观察给结论，提交边界不作为远端持久化的证据。 |
| E01 | P0 | 在单独的耐久性环境中留下待处理或本地草稿、已应用提案和归档状态。重启该宿主，重新打开历史会话和技能演进。 | 已设置模式、应持久化的提案与归档状态均恢复，回滚或恢复入口仍工作。用 `/skill-review` 检查有可比证据且无新活动的会话，不产生重复提案或写入。 |
| E02 | P1 | 从「插件」禁用候选，观察面板和命令。重新启用并重启。用独立一次性 profile 做卸载验证。 | 禁用/卸载后插件入口、复盘能力按宿主生命周期移除。重新启用后在有保留数据的 profile 恢复预期状态。OpenViking 夹具内容独立核对。 |
| E03 | P1 | 检查一次真实模型或确定性模型复盘的诊断，夹具包含正常文本、推理块，另测超时或异常流。用现有单测验证保留策略。 | 合法答案不被推理块污染。模型路径的日志可核对类型、时长、字节与可用错误信息，正文、推理文本、凭据均不落入诊断文件。最多 256 文件且超过 7 天的本插件日志会被清理。快捷确定性提案路径可以没有模型流日志。 |
| E04 | P1 | 在两种主题下用键盘打开高级设置、展开运行详情与提案预览。测试窄窗口、加载、刷新和断连后恢复。 | 菜单路径可找到，操作反馈、焦点和预览可读。长 URI 与 diff 可查看，关键动作在窄窗口仍能触达。断连时有反馈，恢复连接后可刷新。仅对实际复现的表现判定。 |

## 3. 并行分工与验收记录

- 五个子 agent 分别负责 A 安装设置、B 复盘、C 写入与治理模式、D 生命周期和记忆、E 持久化与界面。A02 的离线状态由 A 单独制造。C01 → C02 共用同一提案并由 C 顺序执行。E 复现自己的耐久性数据。所有会产生会话事件的操作在隔离宿主里的**普通会话**完成。
- 参考脚本分层取证。[打包安装冒烟](../test/release-smoke.py)在隔离 DSH Web 启动两代宿主。[宿主模型集成](../test/dsh-v02-web-integration.mjs)可测试真实 DSH 配确定性模型，[浏览器冒烟](../test/dashboard-smoke.mjs)包含替代后端，[流诊断测试](../test/review-stream-log.test.js)覆盖日志规则。执行前阅读各脚本的环境变量和写入范围。报告标注每条证据的来源。
- 建议每组输出 `qa-results/<RUN_ID>/<组>/report.md`，证据保存在该组目录。每例记录 `ID | PASS / FAIL / BLOCKED / NOT_RUN | 候选哈希与测试层 | 实际表现 | 证据路径`。失败另列预期、最短复现、复现次数、严重度、影响范围。会话事件序号、提案 ID、回读哈希和脱敏日志配合使用。有视觉问题时附截图或短录屏。
- 主 agent 核验全部 P0 证据，复核失败归因与阻塞前置，汇总到 `qa-results/<RUN_ID>/report.md`。所有 P0 逐例通过才标记主流程通过。P0 失败时给出缺陷，P0 阻塞或未执行时保留未完成结论。收尾前确认测试进程、端口及测试账号资源的剩余状态，保留脱敏证据。

## 4. 给执行会话的 Prompt

```text
你是技能演进插件的验收负责人。在 dsh-openviking-skill-evolution 仓库中先读 docs/user-acceptance-test.md，按文档实际执行，交付逐例结果与证据。

先固定同一候选包，核对 SHA-256、实际加载版本和隔离条件。以含发布后修复的 0.2.5 候选为首测基线。若取得的只有公开同名包，按文档记录基线差异或从固定源码快照单独打包。不要用版本号判断二者相同。

用 subagent 并行派发五组 A、B、C、D、E，每个 brief 写明用例、候选哈希、夹具、读写范围、输出目录和证据要求。显式路由前用 list_subagent_models 核对，优先使用 deepseek-official/deepseek-flash。若不可用，沿用可用路由。每个子 agent 先查技能目录并加载匹配技能与工具。每组独占 profile、Documents、端口和测试数据。共享浏览器或写入目标的操作由主 agent 串行调度。

测试步骤中的对话用隔离 DSH 宿主里的普通会话。面板操作用真实界面，服务与模型夹具能补齐确定性覆盖。按文档记录真实模型、真实 OpenViking、宿主配夹具和源码/单测各自的覆盖。可用时走一遍真实模型自然对话。生产 profile 与技能库只作为隔离对象，所有改动限于测试资源和报告目录。

各组写 qa-results/<RUN_ID>/<组>/report.md，逐例给出 PASS、FAIL、BLOCKED 或 NOT_RUN，并记录预期、实际、候选哈希、证据路径及缺陷复现步骤。主 agent 核验全部 P0，复查失败和阻塞后写 qa-results/<RUN_ID>/report.md。用例标记示例：B01 | PASS | 候选 SHA-256 + 真实宿主 UI | 留空命中 A，显式 ID 命中 B | history-a.txt、history-b.txt。证据先脱敏。完成后交付总报告与问题清单，并说明剩余测试资源。测试期间不修改插件实现，不提交或推送。
```
